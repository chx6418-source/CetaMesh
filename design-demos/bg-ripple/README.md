# 主题背景渐变 · 湖面涟漪（bg-ripple · 定版 V1「涟漪原波」）

把「起始背景 → 目标背景」的颜色过渡做成**湖面涟漪扩散**的样子。
现在的落点是**进入主页面（控制台）的那一刻**：从登录页转场铺下的同一主题底色，涟漪扩散到**当前主题自己的画布**。

- 登录页**不做任何渐变动画**（`public/token-login.html` 保持原样，一点涟漪都没有）。
- 控制台落场播**一次**：主题是哪个就扩散到哪个 —— 这就是与主题的联动。
- 首轮出过 5 版参数方案，选定 V1 后其余 4 版与其机制已删除（参数记录见 `AGENT_CONTEXT.md` §2 T23）。

## 四套背景配方（来自参考图，配色取自控制台真实 token）

| 键 | 对应 | 来源 |
| --- | --- | --- |
| `base` | 起始基座 | 参考图 1 = 登录页自身背景（linear 150deg + 左上白光 + 右下冷光）；只在 lab 的「三组循环」模式里用 |
| `soda` | 目标 A 苏打 | 参考图 2 = 控制台 light 主题 `.bg-decor`（linear 130deg `#d5e3ff→#ded7ff→#ccf1ef` + 三光斑 + 顶部白雾） |
| `deep` | 目标 B 深海 | 参考图 3 = 控制台 dark 主题 `.bg-decor`（`#182347→#1c1d42→#12262e` + 蓝紫青光斑） |
| `warm` | 目标 C 护眼 | 参考图 4 = 控制台 warm 主题 `.bg-decor`（`#eaeddd→#e7ebe4→#e4eee8` + 灰绿光斑） |

主题映射（`RippleBg.THEME_MAP`）：`light → soda（底色 #eef2fc）` / `dark → deep（#131a2e）` / `warm → warm（#eaede0）`。
底色就是控制台 `--bg`，也正是登录页 `.morph` 退场铺满的那个颜色 —— 所以跨页零色差。

## 两种用法（`ripple-bg.js`）

| 模式 | 用在哪 | 时间轴 |
| --- | --- | --- |
| `once` | 生产：控制台落场 | 起始 →（扩散 `duration`）→ 落定，播完回调 `onDone`，宿主把这一层撤掉 |
| `loop3` | 参考：lab 演示最初那三组「起始图 → 第 N 张目标图」 | 起始 ↔ 三套主题画布循环（扩散 1.55s → 停留 1.10s → 回落 1.35s → 静息 0.80s） |

```js
new RippleBg({ canvas, mode: 'once', from: { solid: '#131a2e' }, to: 'deep',
               duration: 1500, autoplay: true, onDone() { /* 撤层 */ } });
```

### 定版参数（`PRESET`）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 起波点 | uv(1.02, 1.02) | 右下角略出屏，与登录页退场 `.morph` 同向 |
| **波列速度** | 波前速度 × **0.85** | 关键项：波列与波前**同源同速**（`waveRate = span ÷ 时长 × travel`），涟漪跟着波前一起跑；真实水面波峰略慢于波前 |
| 波峰 / 涟漪环 | 7 / 11 | 源到最远角的波峰个数 / 同心涟漪环环数 |
| 振幅 · 耗散 | 0.042 · 1.05 | 波列扭曲波前的幅度 · 涟漪随距离衰减 |
| 边界柔和 · 频散 | 0.038 · +0.55/field | 染色边界宽度，且随距离继续变糊（远处的波前更散） |
| 有机扰动 | 0.016 @1.6 | 低频大尺度 + 高频小尺度，湖面不是完美几何 |
| 波峰亮线 | 0.070（近细远宽） | 水波折射的亮边，宽度与强度随距离衰减 |
| 波面折射 | 0.0045 | 沿波前法线微位移，像透过水波看背景 |
| 涟漪包络 | `sin(πp)^0.85` | 起落两端为 0 → 首尾都是干净的静止色 |
| 落定静止 | 抖动不含时间项 | 落定后画面逐帧完全一致（读回校验为「三次渲染完全相同」） |
| 重烘策略 | 宽高比变化 >2% 才重烘 | 滚动条出现/消失（宽度变 ~0.4%）不会换掉正在播的纹理 → 不会「断层」 |
| 渲染上限 | 2.4M 像素 | 4K/超宽屏自动降采样（纯平滑背景不可感知） |
| 落场纹理精度 | `longSide: 1024` | 末端帧与官方主题底图平均差 ~1/255 |

## 融合的三条硬约束（`check-fusion.mjs`）

- **① 控制台零改动**：`public/console.html` 剥掉全部 `bg-ripple` 标记块后，与基线逐字节相同
  —— 融合只做"新增"，控制台的主题体系 / 落场卡片浮升 / 全部交互逻辑一个字符都没动。
- **② 登录页无涟漪**：`public/token-login.html` 与基线逐字节相同 —— 渐变只在进入主页面时出现。
- **③ 引擎一致**：控制台内联的引擎副本与 `ripple-bg.js` 逐字节相同（桥接只服务两个固定 HTML，
  没有静态资源通道，所以引擎必须内联；改了引擎请重跑 `fuse-console.mjs`）。

## 落场层的细节与降级

- **图层位置**：排在 `.bg-decor` 之后、同为 `z-index:-1` —— 同级按文档顺序绘制，所以它盖住主题画布，
  但仍在所有内容（含毛玻璃面板）之下；毛玻璃面板的取景始终是"本色"背景，不会出现深色主题下被浅色底冲淡。
- **平时不参与渲染**：`.ripple-bg` 默认 `display:none`，只有 `html.login-arrive`（登录页写入标记、控制台 head 消费后打类）才显示；
  普通刷新时这一层根本不存在，也就不会遮挡 `.bg-decor`。画布自带 `background: var(--bg)` 兜底，首帧不闪。
- **落定即交还**：扩散结束回调 `onDone` → `destroy()` + 移除画布，背景交还给控制台自己的 `.bg-decor`。
  实测撤层前后**平均通道差 0.001、峰值 2/255、平均色完全一致**（烘焙复刻与原 CSS 画布几乎逐像素相同）。
- **主题被切换**：`MutationObserver` 监听 `data-theme`，一旦变化立刻收尾撤层，不让这一层挡住新主题。
- **无 WebGL / `prefers-reduced-motion: reduce`**：直接移除这一层，控制台回落到自己的画布，观感与功能不受影响。
- **运行时控制**：`window.__arriveRipple` 暴露 `pause()` / `play()` / `setTime(ms)` / `destroy()`。

## 实测数据

- **落定帧 vs 官方主题底图**（2560×1440 逐像素，与落场同参数 longSide 1024）：
  平均通道差 苏打 **1.08** / 深海 **1.05** / 护眼 **0.96**，峰值 6/6/5 —— 末端与主题背景一致。
- **撤层无痕**（2560×1440，落定后「带画布」vs「撤画布」整幅）：平均差 **0.866 / 0.866 / 0.845**，
  >6 的像素占比 0.01%（仅一处 UI 元素在两次截图间变化），平均色完全相同。
- **本层逐帧平滑**（确定性步进读回画布）：差值平滑钟形 0.67→4.86（峰在 300–400ms）→ **1500ms 时 0.002**，
  且落定后连续渲染结果完全一致（彻底静止）。
- **真实落场时序**（2560×1440）：rAF 帧间隔 **p50 16.7 / p95 16.8 / max 16.8ms，长帧 0 个**；画布尺寸全程稳定（无中途重烘）。
- **三主题联动的落场**：峰值 p 均为 1.0、画布撤除 1504/1508/1506ms、`data-theme` 写入 0 次、控制台自身 2s 清理照常。
- **融合合规**：`check-fusion.mjs` 三条 PASS。

## 修复记录（T26–T30：断层 / 末端不符 / 整页横移 / 跨页硬切）

用「录屏逐帧差值曲线」定位到四处问题，均已修复：

1. **光斑层 `inset` 符号写反**：`.bg-decor::before` 的 `inset:-22%` 是向外扩张，复刻时整层被平移 0.44W/0.44H，
   导致烘出的目标背景**顶部区域**与真实主题画布不符（底部却几乎一致）→ 落场末端撤层时出现可见跳变。
2. **中途重烘**：视口宽度变 ~0.4%（滚动条出现/消失）就重烘纹理，正在播的涟漪被换图 → 「时不时断层」。
   现在只在**宽高比变化 >2%** 时才重烘。
3. **抖动噪声带时间项**：落定后画面仍在极轻微闪烁（逐帧差尾部停在 0.15 不归零）。改为静态抖动后，落定帧逐帧完全一致。
4. **加载期整页横移**（T27）：控制台的异步数据到齐时页面高度会跨过「一屏」临界点，滚动条出现/消失
   让整页横向位移一个滚动条宽度（本机 9~15px），观感像动画断层且时间点紧跟在落场之后。
   做法：随落场层一起加 `html { overflow-y: scroll }` 常驻滚动条槽（控制台自定义滚动条轨道为透明，
   常驻槽位视觉无变化）。注：本机实测 `scrollbar-gutter: stable` **无效**（未预留槽位），故用 `overflow-y: scroll`。
5. **背景先冻住、末尾突跳**（T28）：动画时钟按帧累加 `dt`，而控制台首屏要建大量 DOM + 发多个请求，
   会把主线程堵住 1.5–2s，rAF 一起被饿死 —— `elapsed` 只走到 33ms，画布长时间停在 p≈0（基座色），
   主线程空出来后动画才播、且已比卡片浮升晚一大截。修法：
   ① **动画时钟等页面能稳定出帧才起算**；② **显隐只由接线脚本的内联样式控制**，不挂 `html.login-arrive`；
   ③ **落定后淡出再撤层**（`transition: opacity .3s` + 340ms 后移除）；④ 长卡顿（>250ms）直接落定，不硬撑。
6. **【真凶】负 z 层被 body 背景吞掉 —— 这一层其实一直不可见**（T29）：画布用 `z-index:-1`，而控制台的
   底色写在 `body { background: var(--bg) }` 上；Chromium 会把它当普通元素背景绘制并盖住负 z 层，
   于是**屏幕上看不到画布的 WebGL 内容，只剩画布的 CSS 兜底色**（`background: var(--bg)` = 基座纯色）。
   表现就是「背景冻住 / 只有局部有动画 / 末端与主题图不符」，而读画布内部像素却完全正常 ⇒ 前几轮
   「验证通过」全是假阳性。修法（规范且视觉一致）：**底色从 `body` 挪到 `html`、`body` 透明**
   （`html{background:var(--bg)}` + `body{background:transparent}`），负 z 层即可正常合成；
   另把 `preserveDrawingBuffer` 默认改为 true。实测 `translateZ(0)`/`will-change` 无效、`overflow-y` 与兜底色无关。
7. **登录页主题铺色的圆心漂移、末帧未覆盖**（T30）：旧 `.morph` 把圆形包围盒的右下角放在视口右下角，
   再围绕这个角缩放；圆心会随缩放向左上移动，软边最终从右下重新退出画面。深海主题最明显：跳页前仍留有
   大块浅色斜面，下一帧却直接进入纯深色控制台。现在把圆心固定在视口右下角，保持 240vmax 合成层尺寸并
   放大到 1.35 倍；终态 90% 纯色半径为 **145.8vmax**，严格大于任意视口对角线的 **141.5vmax** 上限。
   扩散改为 840ms 对称缓入缓出，并在 `animationend` 后保留 120ms 完整主题色静帧再跳页（另有 1100ms 兜底）。

**验收口径（重要）**：这一层必须**看屏幕**——把宿主内容 `visibility:hidden` 做隔离观测，对截图取点与
官方主题底图逐点比对（ACC-2 / ACC-7）。只读画布内部像素或只看动画差值会漏掉"内容正确但没被合成"。
参考实测值：深海 左 #1a1f42 / 上 #252749 / 右 #152033 / 下 #1b2d43（官方 #1a2145 / #262a4c / #172338 / #1b2641）。
