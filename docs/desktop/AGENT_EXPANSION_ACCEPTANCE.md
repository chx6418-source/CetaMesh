## SEA provenance and opt-in gate

`npm test -- --suite test-agent-expansion-sea` requires the explicit `WHALEBRIDGE_AGENT_EXPANSION_SEA_DIR` environment variable. Missing opt-in is runner-classified NOT_RUN_ENVIRONMENT. Supplying a nonexistent, malformed, stale or tampered directory is FAIL. No default `dist/core`, release search or source-mode fallback is allowed.

A future authorized build writes `runtime-manifest.json.agentExpansion = { contractVersion: 1, sourceFingerprint }`. The fingerprint covers the fixed Agent runtime input list in `src/agent/expansion-provenance.js`, including adapters, protocol, SDK resource helpers, dispatch, service composition and build script. It is a bounded Agent source identity, not a full-product reproducibility assertion or security readiness flag. The test checks this metadata against current source and executable SHA256 before launching the explicitly selected executable. A local editable manifest is provenance consistency evidence, not a signed supply chain attestation. Future builds also inventory actual copied resources including optional SDK notices and hashes.

The SEA suite removes system Node from PATH, uses an isolated data/profile/temp directory, launches only `--help` and private `--agent-sdk-runner claude`, and bootstraps with a fake credential, empty tools and a nonexistent executable. If the manifest declares the exact pinned SDK resource, initialization must succeed. Absent SDK must return the transport's fixed RPC_REMOTE_ERROR / -32603 envelope, and the result records sdkLoaded=false; this is an unavailable-path check, not SDK SEA success. It never sends `session/new`, prompt/query, starts the worker or connects Owner IPC. Source fixtures cover fingerprint/source mutations, stale contract metadata, executable tampering, fixed executable path and the optional-resource/error-envelope selection. Existing registered `test-core-entry` and `test-agent-claude` cover dispatcher and same-Core launch contracts; these are not actual SEA acceptance.
